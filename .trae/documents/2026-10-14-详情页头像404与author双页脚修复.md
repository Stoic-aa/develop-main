# 详情页作者头像 404 与 author.html 双页脚修复

- 日期：2026-10-14
- 分支：`autosar`
- 相关提交：`1fafbb4`、`3bc2783`

---

## 一、问题

用户点击文章链接进入阅读页后，作者信息区（`Ethan · 阅读时间 8 分钟`）左侧的头像不显示。

## 二、根因

数据源与页面的路径基准不一致。

| 资源 | 书写基准 | 示例 |
| --- | --- | --- |
| `authorAvatar` / `coverImage`（数据源字段） | 站点根目录 | `./picture/author.webp` |
| 正文内嵌图片（`articles/content/*.html`） | `articles/` 目录 | `./picture/xxx.webp` |

列表页在站点根目录，`./picture/author.webp` 解析正确；详情页位于 `/articles/` 子目录，同一字符串被解析成 `/articles/picture/author.webp` → **404**。

该错误路径此前恰好命中一份重复副本 `articles/picture/author.png`，所以问题被掩盖；P0 清理重复文件后（提交 `67845e4`）才暴露，属于该清理引入的回归。

HTTP 实测确认：

- `picture/author.webp` → 200
- `articles/picture/author.webp` → 404

## 三、改动链路

### 1. `1fafbb4` — 修复头像 404

文件：`MyBlog/js/article-detail.js`（+26 / −17）

在文件内新增两个私有工具函数，把「相对站点根目录」的路径统一转换：

```js
/** 计算从当前页面回退到站点根目录的相对前缀（详情页在 /articles/ 下需回退一级） */
function siteRootPrefix() {
    const segments = window.location.pathname.split('/').filter(Boolean);
    return segments.includes('articles') ? '../' : '';
}

/** 将「相对站点根目录」的资源路径转换为当前页面可用的相对路径 */
function resolveAssetPath(assetPath) {
    if (!assetPath) return '';
    // 外链或站点根绝对路径原样返回
    if (/^(https?:)?\/\//.test(assetPath) || assetPath.startsWith('/')) return assetPath;
    return siteRootPrefix() + assetPath.replace(/^\.\//, '');
}
```

- 头像赋值改为走解析器：`els.avatar.src = resolveAssetPath(article.authorAvatar)`
- 原有的 `resolveContentPath()` 内部本身就有一份等价的前缀回退逻辑，一并收敛为复用 `siteRootPrefix()`，消除重复实现。

### 2. `3bc2783` — 移除 author.html 硬编码页脚

文件：`MyBlog/author.html`（−5 行）

页面同时存在硬编码的 `<footer>© 2024 THE MONOLITH…` 与 `#footer-placeholder`（由 `components/footer.html` 注入），导致渲染出两个页脚。删除硬编码块，保留占位符，与 `index.html` 保持一致。

> 说明：`articles/article-template.html` 中的 `<footer>` 是文章自身的标签/操作区，不属于重复页脚，未改动。

## 四、验证

浏览器桥接不可用，改用等价路径解析 + HTTP 状态码验证：

- 修复后解析 `../picture/author.webp`（相对 `/articles/article-template.html`）→ `/picture/author.webp` → **200 image/webp**
- 修复前解析 → `/articles/picture/author.webp` → 404
- 服务端 `js/article-detail.js` 已包含 `resolveAssetPath`
- `author.html` 结构确认：仅剩 `#footer-placeholder` 一个页脚挂载点

## 五、部署后缓存现象（非缺陷）

部署后 `index.html` 内容正常更新，但 `author.html` 需 `Shift+R` 才更新。原因：

- `nginx/cache.conf` 与 `nginx/blog.conf` 的 `Cache-Control: no-cache` 只对**生效之后**返回的响应起作用；
- 生效前浏览器已按 `Last-Modified` 为每个 URL **各自**推算启发式新鲜期，期间不询问服务器、直接用本地副本；
- 缓存按 URL 独立判断，故同一时刻部分页面命中旧副本（author.html）、部分已回服务器（index.html）。

硬刷新一次后即带上 `no-cache` + ETag，后续访问都会协商验证，不再需要硬刷新。

排查命令（服务器侧）：

```bash
curl --noproxy '*' -k -s -o /dev/null -D - "https://www.mylog.world/author.html" --resolve "www.mylog.world:443:127.0.0.1" | grep -i "cache-control\|etag"
curl --noproxy '*' -k -s -o /dev/null -D - "https://www.mylog.world/components/footer.html" --resolve "www.mylog.world:443:127.0.0.1" | grep -i "cache-control\|etag"
```

两行均应输出 `Cache-Control: no-cache`。
